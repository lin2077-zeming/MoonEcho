## 2. 一句话目标

MoonEcho 是一个纯 MoonBit、本地优先的音频指纹检索与音频对齐引擎。给出一段短音频，它能在离线音频库中定位这段音频来自哪个文件、出现在第几秒，并给出可解释的匹配置信度。

## 3. 背景与选题理由

MoonBit 生态已有 WAV 读写、OGG/Opus 解码、FFT/STFT、音频 DSP 和音频引擎等基础项目，但缺少从音频输入到指纹索引、片段检索、时间对齐和置信度评分的完整闭环。

MoonEcho 不重复实现已有底层库，而是在它们之上补齐内容检索层：

- 输入层：PCM/WAV，必要时预留 OGG/Opus 适配接口。
- 特征层：STFT、对数频谱、频谱峰值。
- 指纹层：峰值配对、哈希编码、稳定快照格式。
- 检索层：倒排索引、时间偏移投票、候选择优。
- 应用层：CLI、WASM 演示、JSON/Markdown 报告。

该项目边界清晰，适合在一个月内交付，并且具备真实用途：

- 音频素材库去重。
- 播客广告和固定片段的重复检测。
- 视频剪辑中的音轨对齐。
- 本地音乐识别。
- 浏览器内离线音频检索。

## 4. 项目目标

### 4.1 必须完成

- 提供纯 MoonBit 实现的 PCM/WAV 读取和预处理能力。
- 实现确定性 STFT、对数频谱和频谱峰值提取。
- 实现音频指纹编码和可持久化索引快照。
- 实现查询片段匹配，返回文件、时间偏移和置信度。
- 提供至少一个可运行 CLI 示例。
- 提供一个 WASM 或浏览器可演示路径。
- 提供完整测试、CI、README、许可证和 mooncakes.io 发布材料。

### 4.2 推荐完成

- 支持增量向索引追加音频。
- 支持白噪声、音量变化、静音填充和裁剪。
- 支持索引快照版本升级与校验。
- 提供 Top-K 候选和匹配解释报告。
- 提供基准测试，记录准确率、延迟和内存开销。

### 4.3 暂不纳入

- 不实现完整音频编解码器矩阵，首期只保证 PCM/WAV 链路。
- 不训练神经网络模型，先使用经典声学指纹算法。
- 不实现云端服务、账号系统或数据库服务。
- 不直接复制 Chromaprint、Dejavu 或其他上游项目代码。
- 不提交版权不明的音乐或测试音频。

## 5. 核心用户故事

1. 作为素材库维护者，我希望对音频库建立索引，找出重复或高度相似的音频文件。
2. 作为视频剪辑者，我希望输入一段背景音乐片段，系统返回它来自哪个音乐文件以及时间点。
3. 作为播客制作者，我希望发现节目中重复出现的片头、片尾或广告片段。
4. 作为浏览器应用开发者，我希望在本地 WASM 环境中完成匹配，不上传音频。
5. 作为 MoonBit 开发者，我希望把 MoonEcho 作为库集成到自己的音频处理项目中。

## 6. 功能范围

### 6.1 音频预处理

- 读取 WAV/PCM 数据。
- 支持 8/16/24/32 位 PCM 和浮点 PCM 的基础读取。
- 多声道降为单声道。
- 重采样到统一采样率。
- 分帧、窗函数和静音检测。

### 6.2 频谱特征

- 实现或封装确定性 FFT。
- 生成短时傅里叶变换频谱。
- 计算对数幅度谱。
- 提取局部频谱峰值。
- 支持可配置频率范围、帧长、跳步和峰值密度。

### 6.3 音频指纹

- 将峰值配对编码为稳定哈希。
- 指纹包含频点、时间差和哈希摘要。
- 提供确定性编码与解码格式。
- 提供快照版本号、校验和和边界检查。

### 6.4 检索索引

- 基于哈希建立倒排索引。
- posting list 记录音频 ID 和时间位置。
- 查询时统计时间偏移投票。
- 支持候选过滤、Top-K 排序和置信度计算。
- 支持索引快照保存、加载和校验。

### 6.5 匹配与报告

- 返回最佳匹配文件和偏移时间。
- 输出候选列表和命中证据。
- 支持 JSON、Text 和 Markdown 报告。
- 对误报、低置信度和不匹配给出明确原因。

### 6.6 CLI 与演示

- `moonecho index`：建立索引。
- `moonecho match`：查询片段。
- `moonecho inspect`：检查指纹或快照。
- `moonecho bench`：运行基准测试。
- `moonecho demo`：运行最小端到端示例。
- WASM 路径优先做单文件或小音频集演示。

## 7. 系统结构

建议仓库结构：

```text
MoonEcho/
  docs/
    任务规划书.md
    项目申报书.md
    算法说明.md
  src/
    pcm/
    spectrum/
    fingerprint/
    index/
    match/
    report/
  cmd/
    moonecho/
  examples/
    basic/
    match-clip/
  testdata/
    generated/
    fixtures/
  bench/
  wasm/
  .github/workflows/ci.yml
  LICENSE
  README.md
  moon.mod.json
  moon.pkg
```

包边界原则：

- `pcm` 只处理音频样本和格式。
- `spectrum` 只处理频谱和峰值。
- `fingerprint` 只处理指纹编码。
- `index` 只处理索引结构和快照。
- `match` 只处理候选评分和置信度。
- `report` 只处理输出格式。
- `cmd/moonecho` 只负责参数解析和串联流程。

## 9. 测试策略

### 9.1 单元测试

- PCM 字节序和样本格式转换。
- 单声道化和重采样边界。
- FFT/STFT 对已知信号的输出。
- 峰值提取对合成信号的确定性。
- 指纹哈希编码和解码。
- 索引插入、查询和快照 round-trip。
- 匹配评分和置信度边界。

### 9.2 集成测试

- 对音频库建索引，再查询完整曲目。
- 查询裁剪片段。
- 查询带静音片段。
- 查询带噪声片段。
- 查询带增益变化片段。
- 查询不相关音频作为负样本。

### 9.3 属性测试与模糊测试

- 任意合法 PCM 数据不应导致崩溃。
- 任意截断快照应返回结构化错误。
- 索引加载后查询结果应与原始索引一致。
- 指纹编码解码应满足 round-trip。

### 9.4 质量指标

建议首期目标：

- 干净裁剪片段 Top-1 命中率：大于或等于 98%。
- 时间偏移误差：小于或等于 0.5 秒。
- 加噪片段 Top-1 命中率：大于或等于 90%。
- 负样本误报率：小于或等于 1%。
- 基准测试可重复运行。

上述指标可根据实际测试集调整，但必须在 README 中如实记录。

## 12. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| FFT/STFT 性能不足 | 大音频索引慢 | 先处理短音频，使用固定配置和性能基准，必要时优化窗长和跳步 |
| 鲁棒性不足 | 噪声或变速后匹配失败 | 先完成裁剪、静音、增益和低噪声，变速作为增强项 |
| 测试音频版权风险 | 影响开源合规 | 只使用生成音频和 CC0 素材 |
| 范围过大 | 无法按期验收 | 冻结首版范围，编解码器和神经网络模型全部后置 |
| 索引快照不兼容 | 后续维护困难 | 快照带版本号、校验和和迁移策略 |
| WASM 演示耗时 | 影响文档和发布 | WASM 只做最小演示，核心验收以 Native CLI 和库为准 |
| 与已有项目重叠 | 影响评审 | 明确 MoonEcho 是检索层，不重复 DSP、解码和音频引擎 |
